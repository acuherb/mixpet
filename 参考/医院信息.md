## 1. 设计要点（关键决策）

- **单行配置表**：医院信息是全局单实例，用一张 `id=1` 的单行表，不做增删、不做历史、不做多医院。
- **读写权限**：`GET` 公开（打印页/顾客端都要读）；`PUT` 仅 `MANAGER`。
- **注入方式（重点）**：
  - **打印页**（病历/发票）会 `window.open`/内联 HTML 独立渲染，**不能依赖前台全局 store**，必须**自己拉一次 `/setting/hospital`** 再拼抬头，保证打印时必有数据、且不是启动缓存的旧值；
  - **贴面（首页/页脚/title）** 用前端 `hospitalStore`（App 启动拉一次缓存）。
- **未填写兜底**：接口为空时各注入点显示占位或隐藏，不报错、不崩页面。

## 2. 后端

### 2.1 增量 SQL（`db-backup/feature_20261017_hospital_setting.sql`）

```sql
CREATE TABLE IF NOT EXISTS `hospital_setting` (
  `id`         TINYINT      NOT NULL DEFAULT 1,
  `name`       VARCHAR(64)  NOT NULL DEFAULT '' COMMENT '医院名称',
  `address`    VARCHAR(160) NOT NULL DEFAULT '' COMMENT '地址',
  `phone`      VARCHAR(32)  NOT NULL DEFAULT '' COMMENT '联系电话',
  `logo`       VARCHAR(255) DEFAULT NULL COMMENT 'logo文件名(复用common/download)',
  `biz_hours`  VARCHAR(64)  DEFAULT '' COMMENT '营业时间',
  `intro`      VARCHAR(255) DEFAULT '' COMMENT '简介/简介文案',
  PRIMARY KEY (`id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='医院基础信息(单行配置)';
INSERT INTO `hospital_setting` (`id`) VALUES (1) ON DUPLICATE KEY UPDATE `id`=`id`;
```

### 2.2 实体 + Service

- `entity/HospitalSetting.java`（`@TableName("hospital_setting")`）。
- `IHospitalSettingService extends IService<HospitalSetting>`：
  - `HospitalSetting get()`：`SELECT * WHERE id=1`（无则给空对象，不抛异常）；
  - `Result update(HospitalSetting s)`：固定 id=1 保存，返回 `Result(code=1)`。
- 不做分页/列表/删除。

### 2.3 Controller — `SettingController`

```java
@RestController @RequestMapping("/setting")
public class SettingController {
    @Autowired private IHospitalSettingService s;

    @GetMapping("/hospital")
    public Result hospital() { return Result.success(s.get()); }

    @PutMapping("/hospital")
    @Secured(RoleConst.MANAGER)
    public Result saveHospital(@RequestBody HospitalSetting setting) {
        return s.update(setting);
    }
}
```

- `logo` 存文件名（相对 `common/download?name=`），不做文件内容入库，上传沿用现有组件。
